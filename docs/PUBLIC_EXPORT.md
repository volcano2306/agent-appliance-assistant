# 源码整理与隐私处理

## 导出范围

采用明确的源码目录清单导出，而非复制原仓库后再尝试删除秘密。原项目 `AI/.env` 从未被读取、解析或复制。仅使用公共的 `.env.example` 作为配置字段来源。

| 原目录 | 公开目录 | 保留 |
| --- | --- | --- |
| AI | agent | app、tests、合成 fixtures、tokenizer 与许可证、依赖模板 |
| BE | backend | src、测试、pom；重写为环境变量式公共配置 |
| FE | frontend | 原生小程序源码、测试、UI 图片和字体、依赖锁定文件 |
| 其他 | docs、scripts、data | 新的项目说明、发布检查、合成演示数据 |

## 排除内容

- 所有真实 dotenv 配置、私钥、原 AppID 与本地私有开发者配置。
- `.git` 历史、IDE/自动化助手设置、临时锁文件和旧备份。
- 日志、崩溃转储、缓存、虚拟环境、依赖安装目录、Maven target 和二进制构建产物。
- 原 MongoDB/Qdrant 数据、用户上传资料、原始说明书/PDF/Excel/Word、打印稿和个人工作目录。
- 模型评测逐条原始回包、历史日志和实验报告。评测源码、合成测试样例及用于重现缺陷的最小脱敏 fixture 保留，已去掉原运行路径；不能把它们当成当前模型收益证明。

## 副本调整

- `AI/BE/FE` 统一改名 `agent/BE/frontend`，修正跨模块路径。
- 小程序 AppID 改为 `touristappid`，项目名改为公共名称；业务邮箱改为保留的 `example.com` 示例地址。
- 个人电脑路径改为相对路径或环境变量；真实测试的 dotenv opt-in 入口只指向当前公开副本，不再指向原电脑路径。
- 去除 App 启动时的无用日期日志存储。原 `pages/logs` 实际是搜索功能，改名 `pages/search` 并修正导航；不删除用户可主动清空的搜索历史功能。
- 保留必要错误处理和运行时诊断代码；“去除日志”指副本不携带日志文件、真实回包及无用启动记录，不移除业务异常处理。
- Dockerfile 补齐 tokenizer 资源复制，避免容器中的记忆计数缺失文件；提供前后端分离的构建目录和根 Compose。
- 本次整理没有修改原项目业务源码，没有启用记忆功能，没有再次调用模型。

## 发布检查

运行 `python scripts/check_public_export.py`，检查不应发布的文件/目录、硬编码密钥形状、非模板 AppID、个人绝对路径、引用完整性和图片中的文字/Exif 元数据。输出只列出文件与问题类别，不输出疑似秘密的值。

合成测试中包含用于校验报修参数、脱敏逻辑的示例联系方式，它们是测试样例，不是导出的真实用户信息。原数据库和用户数据从源头排除。扫描的“通过”只表示本规则范围没有发现，不代表形式化证明任何字符串都不涉及隐私。

副本没有 `.git`。可在此目录新建仓库后上传；不要把旧 Git 历史或本地运行生成的数据目录重新合并进来。本项目采用 [MIT 许可证](../LICENSE)，第三方资源保留原始许可证。
