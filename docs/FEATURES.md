# 项目功能说明

以下“已实现”指仓库内有对应页面、接口或执行逻辑；完整运行仍依赖本地数据和外部服务配置。测试入口与运行条件见 [测试运行说明](TESTING.md)。

## Agent 能力

**执行控制。** 用有上限的 AgentLoop 完成模型判断、工具执行和结果返回。包含工具参数校验、最多工具轮次、超时处理与最终 JSON 格式修复。

**混合检索。** BM25 与向量双路召回，使用等权 RRF 融合、片段去重、说明书范围过滤。返回引用来源与页码；向量召回失败时可保留 BM25 结果。需要先准备 MongoDB 文本片段；向量索引需额外建立。

**Prompt。** 区分咨询、故障、收藏、报修确认/取消、商品推荐等场景；通过示例和工具 Schema 约束意图、参数来源与输出格式。

| 工具 | 用途 | 执行要求 |
| --- | --- | --- |
| `manual_search` | 检索说明书证据 | 依据已知设备和实际问题检索 |
| `diagnose_fault` | 查询故障相关说明书信息 | 不编造型号/故障码；危险现象优先给出安全处理提示 |
| `add_manual_to_account` | 加入我的说明书 | 需要明确收藏意图及业务对象，Java 负责实际写入 |
| `create_repair_order` | 创建报修单 | 展示已知信息、明确确认，Java 校验并写入 |
| `recommend_internet_products` | 获取联网商品候选 | 需搜索凭据；注明来源，价格和库存由外部结果决定 |

**失败处理。** 根据工具回执区分成功、明确失败和结果未知。参数拒绝不误报执行成功；写请求已发出但超时/异常时保留未知状态，停止自动重复提交；最终回答保留已观察到的执行结果。

## 对话记忆与一致性

默认策略为 `threshold`，阈值 1500 个本地估算文本 token，压缩时保留最近 5 个完整轮次，摘要上限 600 token。不是每轮都只保留五轮：未触发时保留已有摘要和此后的全部完整对话；触发后把更早的新增对话与旧摘要批量压缩。

目标是压缩后明显低于触发阈值，最小增长间隔默认 500 token。若最近五轮本身很长，仍需遵守输入预算，不能保证仅靠压缩旧历史便降低到阈值以下。摘要失败保留原文与已有摘要。

Java 实现会话归属检查、`requestId` 重复请求控制、MongoDB 租约/fencing/CAS 与删除状态保护；前端防止旧回包写入新会话。归属校验是当前 Demo 身份体系下的逻辑隔离，未替代正式认证。
